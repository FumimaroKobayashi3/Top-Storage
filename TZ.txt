Тема: Разработка веб-сервиса файлового хранилища «ТОП» (Территория Общего Пользования)

**Вводная часть и обоснование проекта:**

За время работы над дипломным проектом концепция прошла путь от масштабных идей до создания надежного, легковесного и практичного сервиса. Главная цель работы — показать уверенное освоение пройденного материала, культуру архитектурного проектирования и умение доводить веб-приложение до стабильного рабочего состояния.

В качестве итогового проекта разработан веб-сервис файлового хранилища «ТОП» (Территория Общего Пользования), вдохновленный решениями уровня «Яндекс Диск» и «Облако Mail.ru». Название приложения отражает его суть и одновременно служит отсылкой к Академии ТОП. Проект сочетает модульную архитектуру, удобную работу с медиаданными, строгий контроль серверных ресурсов и прозрачный аудит системных событий.

Технологический стек:

Backend: Python 3.10, FastAPI (ASGI-сервер Uvicorn)
База данных: Встроенная СУБД SQLite (с принудительной активацией режима WAL — Write-Ahead Logging)
Frontend: React 19 SPA, сборщик Vite, CSS Modules (поддержка темной и светлой тем)
Инфраструктура: Docker (двухэтапная сборка Multi-stage build), подключение постоянного тома `/data` (PaaS Amvera), Git

Основные функциональные требования:**

1. Строгое ограничение объема хранилища (дисковая квота):

В приложении реализован жесткий серверный контроль дискового пространства с лимитом в 5 ГБ (5 368 709 120 байт)** под конфигурацию облачного тома. При расчете занятого места агрегируются размеры абсолютно всех зарегистрированных объектов, включая файлы в корзине (`SELECT COALESCE(SUM(FileSize), 0) FROM FILESDB`), так как до момента физической очистки они занимают реальное место на накопителе. При попытке загрузки файла сверх лимита операция блокируется сервером до записи на диск.

2. Контроль целостности и подсистема аудита (SECURITYDB):

Для каждого принимаемого файла на лету рассчитывается 256-битный криптографический отпечаток SHA-256. Первые 8 символов хэша используются в качестве уникального префикса физического имени файла на диске для исключения коллизий и перезаписи. Встроенная подсистема аудита регистрирует ключевые события в таблице `SECURITYDB` (успешная загрузка `UPLOAD_SUCCESS`, превышение лимита памяти `LIMIT_EXCEEDED`, сбои дискового ввода-вывода `DISK_ERROR`) с фиксацией имени, хэша и временной метки.

3. Двухуровневое удаление и управление корзиной:

Реализована модель мягкого удаления (Soft Delete): перемещение файла в «Корзину» исключает его из активного списка, переключая статус `IsTrash = 1`, но сохраняет объект на диске. Пользователь может восстановить файл в один клик без повторной проверки квоты. Окончательное освобождение дискового пространства происходит только при безвозвратном удалении отдельного файла или полной очистке корзины через метод `unlink()`.

4. Встроенный нативный предпросмотр в браузере:

Реализован потоковый просмотр документов и медиафайлов прямо в веб-интерфейсе без необходимости предварительного скачивания на локальный ПК. Поддерживаются:

 Растровые графические изображения (PNG, JPG, JPEG, WebP)
 Текстовые документы (`.txt`) с возможностью чтения в окне просмотра
 Документы формата PDF (отображение через встроенный контейнер `<iframe>`)
 Видеофайлы формата MP4 (воспроизведение через нативный плеер HTML5 Video)
 Аудиозаписи форматов MP3, WAV, M4A (воспроизведение через HTML5 Audio Player)

5. Публичные сгорающие ссылки (шеринг с ограничением времени):

Система поддерживает генерацию временных ссылок доступа для внешних пользователей с выбором периода действия: 2 часа, 5 часов, 24 часа, 72 часа или бессрочно. Проверка срока жизни выполняется сервером при каждом запросе (on-demand) путем валидации Unix timestamp, вшитого в публичный токен. По истечении срока доступ аннулируется автоматически с возвратом HTTP-статуса `410 Gone` без привлечения тяжелых фоновых демонов.
