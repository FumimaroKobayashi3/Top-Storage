Группа: «Python 52»
Компьютерная Академия ТОП
Выполнил: студент Герасименко Н. Н.
Тема: Разработка веб-сервиса файлового хранилища «ТОП» (Территория Общего Пользования)

Вводная часть и обоснование проекта:

За время работы над дипломным проектом концепция прошла путь от масштабных идей до создания надежного, легковесного и практичного сервиса. Главная цель работы — показать уверенное освоение пройденного материала, культуру архитектурного проектирования и умение доводить веб-приложение до стабильного рабочего состояния.

В качестве итогового проекта разработан веб-сервис файлового хранилища «ТОП» (Территория Общего Пользования), вдохновленный решениями уровня «Яндекс Диск» и «Облако Mail.ru». Название приложения отражает его суть и одновременно служит отсылкой к Академии ТОП. Проект сочетает модульную архитектуру, удобную работу с медиаданными, строгий контроль серверных ресурсов и прозрачный аудит системных событий.

Технологический стек:

Backend: Python 3.10, FastAPI (ASGI-сервер Uvicorn)
База данных: Встроенная СУБД SQLite (с принудительной активацией режима WAL — Write-Ahead Logging)
Frontend: React 19 SPA, сборщик Vite, чистый CSS (единая система тем оформления themes.css, переключение темной и светлой темы через селекторы классов)
Инфраструктура: Docker (двухэтапная сборка Multi-stage build), подключение постоянного тома /data (PaaS Amvera), Git

Основные функциональные требования:

1. Аутентификация и многопользовательский режим (USERSDB):

Реализован механизм регистрации и авторизации пользователей по логину и паролю. Пароли сохраняются в базе данных исключительно в виде SHA-256 хэшей. Списки активных файлов, содержимое корзины, а также расчет персональной дисковой статистики на главном дашборде строго привязаны к идентификатору текущего авторизованного пользователя (user_id).

2. Строгое ограничение объема хранилища (дисковая квота):

В приложении реализован жесткий серверный контроль дискового пространства с лимитом в 5 ГБ (5 368 709 120 байт) под конфигурацию облачного тома. При расчете занятого места агрегируются размеры абсолютно всех зарегистрированных объектов конкретного пользователя, включая файлы в его корзине, так как до момента физической очистки они занимают реальное место на накопителе. При попытке загрузки файла сверх доступного лимита операция блокируется сервером до момента сохранения на диск.

3. Идентификация содержимого, защита от коллизий и журнал аудита (SECURITYDB):

Для каждого принимаемого файла на сервере рассчитывается 256-битный криптографический отпечаток SHA-256, который фиксируется в базе данных и системном журнале для точной идентификации и аудита данных. Физическое имя файла на накопителе формируется с добавлением уникального псевдослучайного префикса UUID (uuid.uuid4), что гарантированно предотвращает перезапись данных и файловые коллизии при совпадении исходных имен у разных пользователей. 
Встроенная подсистема аудита регистрирует ключевые события в таблице SECURITYDB (успешная загрузка UPLOAD_SUCCESS, превышение лимита памяти LIMIT_EXCEEDED, сбои дискового ввода-вывода DISK_ERROR) с сохранением имени файла, хэша и точной временной метки.

4. Двухуровневое удаление и изолированное управление корзиной:

Реализована модель мягкого удаления (Soft Delete): перемещение файла в «Корзину» исключает его из активного списка файлов диска путем выставления флага IsTrash = 1, но сохраняет физический объект на накопителе. Пользователь имеет возможность восстановить файл в один клик без повторного прохождения квоты. 
Окончательное физическое освобождение дискового пространства через метод unlink() происходит только при ручном удалении отдельного файла из корзины либо при вызове полной очистки корзины, которая затрагивает исключительно файлы текущего пользователя (WHERE IsTrash = 1 AND UserID = ?).

5. Встроенный нативный предпросмотр в браузере:

Реализован потоковый просмотр документов и медиафайлов прямо в веб-интерфейсе без необходимости предварительного скачивания на локальный ПК. Поддерживаются:
- Растровые графические изображения (PNG, JPG, JPEG, WebP);
- Текстовые документы (.txt) с возможностью быстрого чтения содержимого в модальном окне;
- Документы формата PDF (отображение через встроенный контейнер <iframe>);
- Видеофайлы формата MP4 (потоковое воспроизведение через нативный плеер HTML5 Video);
- Аудиозаписи форматов MP3, WAV, M4A (воспроизведение через HTML5 Audio Player).

6. Публичные сгорающие ссылки (шеринг с ограничением времени):

Система поддерживает генерацию временных ссылок доступа для внешних пользователей с выбором периода действия: 2 часа, 5 часов, 24 часа, 72 часа или бессрочно. Проверка срока жизни выполняется сервером при каждом запросе (on-demand) путем валидации Unix timestamp, вшитого в публичный токен. По истечении срока доступ аннулируется автоматически с возвратом HTTP-статуса 410 Gone без привлечения тяжелых фоновых демонов.
